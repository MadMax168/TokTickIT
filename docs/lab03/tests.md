# Sprint 3 planned test matrix

Status: Draft. All rows are **Planned**; no application/schema/test code is created by this contract task. IDs reference [specification.md](specification.md), endpoint shapes in [api-spec.md](api-spec.md), and screen/state IDs in [ui-spec.md](ui-spec.md). Paths are planned repository-relative locations and use `lab03` per the updated directory convention.

Use Vitest/unit and Testing Library for local behavior, Supertest against exported app with isolated PostgreSQL/storage for APIs, and Playwright against client/API for E2E. Tests require real session cookies/CSRF handling rather than spoofed Requester headers. Controlled clocks and independent cookie jars cover expiry/races. The shared seed fixture includes four active Requesters with disjoint tickets, one inactive Requester, at least three active and one inactive IT Staff, two active Admins, and the 12-ticket distribution in specification §7 across Requesters, all eight statuses, all three Requested/IT Priority values, and assigned/unassigned ownership including an Administrator owner. Include the three Public Comments and two Internal Notes with exact stable seed identities/authors/times/bodies from specification §7. Isolated cases add one-Admin variants, restricted sessions and active/removed files. Never use production credentials or user files.

Status API-16/17 and UNIT-03 must generate the full 8×8 matrix: 16 allowed directed edges and 48 rejected pairs including eight same-state pairs. Run all 64 pairs for each R/S/A role (192 role/pair cases), plus anonymous/restricted session checks, missing owner/reason/confirmation and stale-version variants. A single happy-path flow is not matrix coverage. API-07 and SEC-02 expand over every protected endpoint, including attachment bytes and both note operations. Shared error/state tests expand over each applicable endpoint/screen rather than a representative sample.
